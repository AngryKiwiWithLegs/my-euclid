# 系统架构

## 总体策略

My Euclid 采用**本地优先、云端能力按需启用**的架构。题库、原件、作答、报告、标签、训练指标和用户配置常驻用户设备；云端 AI 仅处理用户主动发起的 OCR、切分、评分、讲解和变式请求。

| 层 | 计划技术 | 职责 |
| --- | --- | --- |
| 桌面壳 | Electron `arm64` | 原生文件选择、摄像头、文件系统、Keychain、DMG 打包。 |
| 界面 | React + TypeScript（手写 CSS） | 档案工作台、题面、手写板、训练流和报告。 |
| 数学排版 | KaTeX（已接入） | 题面中的 LaTeX 片段渲染为公式；无公式或渲染失败时原样显示。 |
| 本地数据 | SQLite（better-sqlite3，手写 SQL + PRAGMA user_version 迁移） | 结构化题库、标签、训练历史、IRT 参数与索引；实现按域拆分在 `electron/db/`。有意不引入 ORM（见 AI-HANDOFF 硬性规则）。 |
| 文件存储 | 应用数据目录 | 原件、切图、手写笔迹、照片、导出档案。 |
| AI 适配器 | 可替换 Provider 接口 | OCR、结构化切分、判卷、讲解、相似题和标签建议。 |

## AI 调用边界

AI 适配器以任务为单位传输最小必要材料：OCR 发送页面图像；评分发送题目、小问、评分规则、参考解答和该小问作答；讲解发送当前题、掌握状态和用户授权的关联题索引。密钥保存在 macOS Keychain，而非导出数据包或普通配置文件。每次调用都需保存时间、任务、材料摘要和结果版本，支持用户审阅与删除。

## IRT 与知识图谱

初始版本记录题目难度、区分度、猜测参数的可编辑先验，以及用户能力参数和标签掌握度。系统用真实作答更新能力估计；当样本量不足时，明确显示“暂缺足够数据”，不假装给出精确能力值。知识依赖图将“复数/代数/几何/计数概率/数论”等概念作为节点，将前置关系作为有向边，用于推题时识别上游补弱路径。
