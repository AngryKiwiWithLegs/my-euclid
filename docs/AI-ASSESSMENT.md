# 逐次授权的 AI 判卷

My Euclid 的真实 AI 判卷只在小明完成一次明确的授权流程后才会发出网络请求。保存作答、切换训练会话、打开错题证据、导入纸质答卷和查看报告均不会触发 AI 请求。软件先从 macOS Keychain 读取已启用的默认提供商配置，在本地生成十分钟有效的一次性授权预览；小明可在预览中核对服务名称、模型、题面文本、答卷文本、答卷形式、满分和附件处理边界。

| 阶段 | 处理内容 | 是否发送到服务商 |
| --- | --- | --- |
| 服务测试与模型发现 | 以保存的密钥请求 `GET /models`，仅返回模型标识、时延和脱敏状态。 | 是，但不发送题目或答卷。 |
| 授权预览 | 读取所选本地答卷版本，展示将要发送的题面、答卷文本和元数据。 | 否。 |
| 明确确认 | 以默认服务的模型向 `POST /chat/completions` 提交题面、答卷文本和满分。 | 是。 |
| 结构化校验 | 验证总分、逐项依据、错因、模块拆分及分数加总。 | 否；完全在本地执行。 |
| 草案审核 | 把合格结果保存为 `origin=ai`、`status=draft` 的本地评分档案。 | 否；必须人工确认后才进入报告。 |

纸质附件、原始图片、扫描 PDF 和笔迹二进制数据**不会**在当前版本的判卷请求中上传。若选中的答卷没有可发送文本，预览会明确指出这一点，而系统不会尝试读取附件内容或以附件猜测答案。用户若需要对纸质答案进行 AI 判卷，应先在本地 OCR 审核工作台确认需要发送的文本。

## OpenAI 兼容协议

自定义提供商需要提供 HTTPS 基地址、模型标识和 Bearer API 密钥。测试连接与模型发现调用 `<baseUrl>/models`；判卷调用 `<baseUrl>/chat/completions`，以 `response_format: {"type":"json_object"}` 要求 JSON 结果。返回结果至少须含有总分、与总分严格相加一致的评分依据、摘要和整体反馈。格式不合规、HTTP 错误、超时或授权过期都不会创建评分草案。

每次已确认的判卷会写入本地 `ai_run_audits`，记录提供商标识、会话/答卷回链、授权时间、请求范围摘要、运行状态和有限响应摘要；密钥不会出现在审计表、SQLite 可见字段、日志、renderer 或备份包中。

## 验证

`scripts/verify-ai-runtime.mjs` 使用本地模拟 OpenAI 兼容服务验证模型发现、未授权拒绝、一次性令牌、发送范围、结构化评分草案、格式错误拒绝和失败审计。运行：

```bash
pnpm build:electron
pnpm exec electron --runAsNode scripts/verify-ai-runtime.mjs
```

这项验证不替代目标 Apple Silicon Mac 上的真实 Keychain、真实服务端权限、模型兼容性和网络环境验证。
