# 可审计评分与报告

## 范围与原则

本阶段实现的是**本地人工评分档案与报告聚合**，而不是未经配置的 AI 判卷。每份评分必须回链一份已保存的训练会话和具体答卷版本；得分结论由可逐项查看的评分依据、错因与模块拆分支持。原始作答、纸质附件、笔迹以及评分数据都保存在本地 SQLite，并随现有备份包导出和恢复。

> 评分记录只有在状态为“已确认”时才会进入长期报告。草稿可保存，但不会影响得分率、模块统计或错因分布。

| 数据实体 | 作用 | 可追溯关系 |
| --- | --- | --- |
| `assessment_records` | 一次人工评分的总分、摘要、整体反馈与版本 | 指向 `practice_sessions` 和 `practice_responses`。 |
| `assessment_evidence` | 逐项得分点、满分、得分、依据与作答摘录 | 属于一份评分档案，可回看具体给分理由。 |
| `assessment_mistakes` | 错因类别、严重程度、知识模块与说明 | 只在确认后进入错因分布。 |
| `assessment_modules` | 模块的得分、满分与备注 | 只在确认后进入模块得分率。 |

## 本地工作流

小明先在“训练会话”保存键盘、笔迹或纸质附件版本，再打开“错题证据”。在该页面选择训练会话及其答卷版本，录入总分、评分依据、错因和模块拆分。确认前，系统会检查每条评分依据的得分不高于该项满分，并要求所有评分依据的合计与总分相等。确认后，评分档案写入本地数据库，报告页按真实确认记录汇总累计得分率、最近得分率、模块表现、错因分布及评分轨迹。

局部 OCR、题目切分和作答版本保持独立。评分说明可引用 OCR 修订后的题面或答卷摘录，但不会覆盖原始资料、页面 OCR、笔迹数据或作答文本。

## AI 判卷边界

当前任务没有已启用、可由用户授权使用的 AI 判卷连接，也没有提供用户的 API 密钥。因此界面会明确显示“AI 判卷尚未配置”，不会生成示例分数、伪造评分依据或把本地人工档案标为 AI 输出。

后续接入需要先完成以下事项：在 macOS Keychain 保存用户提供的密钥；由用户主动点击发起某次判卷；记录模型、请求时间、输入材料版本、输出原文、结构化评分结果和人工确认状态。AI 输出应先作为待审核评分草案，只有小明确认后才计入报告与长期统计。

## 验证

`scripts/verify-assessment-report.mjs` 通过以下路径验证实现：创建真实本地作答版本，保存一份含两条评分依据、一条错因和一个模块拆分的确认评分，验证报告汇总，再导出备份、写入后续草稿并恢复备份，最后确认评分与报告数据一并恢复。运行前执行 `pnpm build:electron`，随后运行：

```bash
pnpm exec electron --runAsNode scripts/verify-assessment-report.mjs
```
