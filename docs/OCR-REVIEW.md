# 页面级 OCR 与切分审核工作流

## 处理范围

My Euclid 将每份导入资料先归档为不可变原件，再从原件生成一个或多个页面记录。TXT 和 Markdown 直接提取为一页文本；PDF 逐页提取可访问的文字层；PNG、JPG、JPEG 与 HEIC 使用本地 Tesseract 引擎进行英文识别。欧几里得原始资料通常以英文呈现，因此当前离线识别优先配置英文模型。扫描 PDF 不依赖文字层：PDF.js 会在本地把指定页栅格化为 PNG 页面预览，再交由同一局部识别路径处理。

## 人工审核

审核工作台以三栏形式展示资料、页面和题目草案。小明可以逐页查看本地 OCR 文本，手动修订后保存。保存会将该页改为“已确认”，但不会删除原件或覆盖原始导入文件。PDF 和图片页面会显示本地预览；拖拽框选区域后，系统仅对裁剪区域再次 OCR，并将坐标、裁剪哈希、预览图、识别文本与状态保存在 `ocr_region_runs`。局部结果不会自动覆盖页面文本；只有人工点击“采用文本”并保存页面，才会写入人工审核版 OCR。随后可从任一页面创建题目草案、调整题号、标题、文本与来源页，并确认写入题目档案。已确认的草案保存在 `question_drafts` 和 `subquestion_drafts`，为后续训练和评分建立可追溯边界。

| 数据层 | 当前状态 | 审核后的去向 |
| --- | --- | --- |
| 原始文件 | 永久归档 | 保留在应用数据目录，不被文本编辑覆盖。 |
| 页面 | 已实现 | 保存页码、OCR 文本、OCR 状态、人工审核状态与原件回链。 |
| 题目草案 | 已实现 | 保存来源页、题号、标题与题面文本。 |
| 小问草案 | 已实现 | 保存到所属题目下，保留题号和文本。 |
| 视觉页标注 | 已实现 | 本地页图、规范化框选坐标、裁剪哈希、缩略图、区域 OCR 文本与状态。 |

## 当前限制

本地图片 OCR 首次运行时可能需要下载语言模型。未能读取的图片不会丢失：系统仍会保存原件、创建该页记录并把状态标为“OCR 待重试”。扫描 PDF 的视觉页渲染和局部 OCR 已实现；当前限制是仅内置英文模型、单页预览与区域裁剪均受本地像素和 8 MB 输出限制约束，且不会自动推断题号或替代人工审核。

## 验证方式

仓库包含 SQLite ABI 冒烟测试、原件归档—页面—题目/小问确认的集成测试、PDF 页面文字提取测试、图片 OCR 测试，以及图片和 PDF 页面预览—局部 OCR—审计回链测试。运行前请先执行 `pnpm build:electron`，以 `pandoc scripts/fixtures/region-ocr-scan-sample.md -o /tmp/euclid-region-ocr-scan-sample.pdf` 生成 PDF 夹具（需本机安装 pandoc），再使用 Electron 的 Node 运行时运行 `pnpm exec electron --runAsNode scripts/verify-region-ocr.mjs /tmp/euclid-region-ocr-scan-sample.pdf`。实际 macOS 界面验证需在 Apple Silicon 目标机中执行 `pnpm dev:desktop`。
