# 页面级 OCR 与切分审核工作流

## 处理范围

My Euclid 将每份导入资料先归档为不可变原件，再从原件生成一个或多个页面记录。TXT 和 Markdown 直接提取为一页文本；PDF 逐页提取可访问的文字层；PNG、JPG、JPEG 与 HEIC 使用本地 Tesseract 引擎进行英文识别。欧几里得原始资料通常以英文呈现，因此当前离线识别优先配置英文模型。对没有文字层的 PDF，页面会保留为待审核状态，后续版本会增加渲染页图像后再次识别的路径。

## 人工审核

审核工作台以三栏形式展示资料、页面和题目草案。小明可以逐页查看本地 OCR 文本，手动修订后保存。保存会将该页改为“已确认”，但不会删除原件或覆盖原始导入文件。随后可从任一页面创建题目草案、调整题号、标题、文本与来源页，并确认写入题目档案。已确认的草案保存在 `question_drafts` 和 `subquestion_drafts`，为后续训练和评分建立可追溯边界。

| 数据层 | 当前状态 | 审核后的去向 |
| --- | --- | --- |
| 原始文件 | 永久归档 | 保留在应用数据目录，不被文本编辑覆盖。 |
| 页面 | 已实现 | 保存页码、OCR 文本、OCR 状态与人工审核状态。 |
| 题目草案 | 已实现 | 保存来源页、题号、标题与题面文本。 |
| 小问草案 | 已实现 | 保存到所属题目下，保留题号和文本。 |
| 视觉页标注 | 后续 | 将增加原页缩略图、框选区域和重新 OCR。 |

## 当前限制

本地图片 OCR 首次运行时可能需要下载语言模型。未能读取的图片不会丢失：系统仍会保存原件、创建该页记录并把状态标为“OCR 待重试”。PDF 文本层的读取也不等同于视觉 OCR；对扫描 PDF，下一阶段会先渲染每页为本地图像，再交给同一识别引擎。

## 验证方式

仓库包含三类本地验证：SQLite ABI 冒烟测试、原件归档—页面—题目/小问确认的集成测试，以及 PDF 页面文字提取测试与图片 OCR 测试。运行前请先执行 `pnpm build:electron`，再使用 Electron 的 Node 运行时启动对应脚本。实际 macOS 界面验证需在 Apple Silicon 目标机中执行 `pnpm dev:desktop`。
